who it's for

A seatbelt for an AI agent in a legacy codebase

You have a large, old codebase with little or no documentation. Nobody holds the whole thing in their head, the rules for what-can-change-where live in people's memory, and letting an agent loose in there is a risk. speclok turns that guardrail from tribal knowledge into a rule the compiler enforces.

No docs, no time to write them

You never stop to document the repo. The spec accretes where work happens: each time you touch a method, you annotate that method. The hot paths get specified over months, and because the spec is an annotation on the code, it cannot silently lie.

Guardrails that keep slipping

"Don't touch billing" lives in an AGENTS.md, a wiki, a senior's head - and it leaks. Here the boundary is @Spec(allowedFiles) + @Protected, blocked at write time, not caught in review.

Too big to hold in context

The agent gets only the slice it needs - the task briefing, over MCP - and is pinned to the declared scope, so it does not wander the other 2,000 files. The benchmark shows it: 3.3% out-of-scope edits vs 77-100%.

It does not make the agent smarter - correctness is flat in the benchmark. It makes it confinable: you do not wake up to a commit in PaymentProcessor.java that nobody asked for.

the spec is the code

Write the contract where it lives

No separate spec file to drift. The contract sits on the class and the method it governs, and an incomplete spec is a compile error, shown inline like a misused @Getter.

@Spec(
  id = "T-200",
  objective = "Shipping must never be negative",
  allowedFiles = {"Shipping.java", "ShippingTest.java"},
  symbols = {"Shipping.calculate"},
  outOfScope = {"change the price table"}
)
public class Shipping {

  @AC(id = "AC1", given = "a subtotal of 50",
      when = "calculate(50) is called",
      then = "returns a fee >= 0, never negative")
  public int calculate(int subtotal) { ... }
}

Leave the objective empty or drop the then, and your IDE underlines it in red:

Shipping.java:2: error:
  spec-lint [T-200]:
  objective is empty

A standard javac error. No agent required.

why

Two things carry the spec today, and both leak

speclok collapses them into one place that the compiler checks and git versions, in the same commit as the code.

Prompts leak

You put the rules in a system prompt, AGENTS.md, .cursorrules - one file per tool. The model follows them... usually. Nothing enforces them, they balloon, and the bigger they grow the more they get ignored.

Markdown specs rot

The real contract scatters across a ticket, a doc, an ADR. The moment the code changes, the doc does not - and an agent led by a stale doc walks into a wall.

AGENTS.md "never negative" .cursorrules "...free over 200" docs/specs/ship.md edited months ago docs/adr/0007.md why we chose it Shipping.java the actual code

how it works

One source of truth, three jobs

From the @Spec/@AC on the code, speclok does all three - deterministically, always in sync.

generates

The docs

The spec book, the per-task agent briefing and the task index - derived from the annotation, never hand-written.

specbook · specctx · sdd list
enforces

The rules

Incomplete spec is a compile error. Edits outside scope are blocked. "Done" is refused until every criterion's test passes.

SpecLintProcessor · scope/compile/accept
serves

The agent

A built-in MCP server hands any AI agent the briefing, the gates and a scaffold tool for new specs.

sdd mcp · JSON-RPC over stdio

Mark credentials, audit or compliance code with @Protected(tier). The scope guard blocks FORBIDDEN edits and checkpoints RESTRICTED ones.

quickstart

60 seconds, just a JDK

The prebuilt harness ships in the repo. Point it at the example - no Maven, no build, Java 11+.

# clone and enter the example
git clone https://github.com/Cherobin/speclok && cd speclok/example

# documentation, generated from the annotations
java -jar lib/speclok.jar specbook src/main/java -o SPECBOOK.md

# the task index, a briefing, and the gates
java -jar lib/speclok.jar sdd list
java -jar lib/speclok.jar sdd briefing T-200
java -jar lib/speclok.jar sdd verify  T-200   # build + the @AC tests
